Let us break this down step-by-step with real examples.
When you run a reasoning model like Qwen, there are two different ways to tell the model to skip thinking.

* Way 1: Using the automatic software toggle (enable_thinking=False).
* Way 2: Manually typing the text tags (<think>\n\n</think>\n\n) directly into the prompt.

Because these two approaches handle text completely differently, vLLM needs a different Reasoning Parser setup for each.
------------------------------
## Understanding the vLLM "Boxes"
Every time a model generates a response, vLLM packages that response into a JSON payload to send back to your application. It has two main "boxes" (or text fields) it can put text into:

   1. reasoning_content: The "Thinking Box" (visible inside dropdowns in chat UIs).
   2. content: The "Final Answer Box" (the regular text shown to the user).

The --reasoning-parser flag tells vLLM exactly how to sort text into these two boxes.
------------------------------
## Scenario 1: The Automatic Parameter Way (enable_thinking=False)
In this scenario, you do not type any tags yourself. You let the Hugging Face/vLLM template engine do the work behind the scenes by sending a parameter toggle in your code.
## Setup:

* Your Code Looks Like This:

extra_body={"chat_template_kwargs": {"enable_thinking": False}}

* Server Flag to Use: --reasoning-parser qwen3

## What Happens Under the Hood:

   1. vLLM looks at your code parameter (enable_thinking=False) and artificially fills the chat template with the closed tags before the model even starts typing.
   2. Because you used the qwen3 parser, vLLM says: "Okay, I see the user used the official Qwen toggle to turn off thinking. I will not look for any thinking tokens."
   3. The model skips thinking and starts typing the final answer right away.
   4. The qwen3 parser safely puts 100% of the model's text into the Final Answer Box (content). No errors, no crashes.

------------------------------
## Scenario 2: The Manual Text Way (Typing <think>\n\n</think>\n\n Yourself)
In this scenario, you completely ignore the enable_thinking code parameter. Instead, you act as a prompt engineer and type the closed tags manually at the very end of your prompt string.
## Setup:

* Your Prompt Looks Like This:

"User: Tell me a joke. <think>\n\n</think>\n\n"

* Server Flag to Use: Omit the flag entirely (Do not type any reasoning parser flag at all).

## Why You Do NOT Use qwen3 Here:
If you use --reasoning-parser qwen3 while manually typing tags, the server gets confused. It expects the software parameter to control the tags, not your manual text string. It will look for template signals that aren't there and will crash or throw an formatting error.
## What Happens Without the Flag (Recommended for Manual Tags):

   1. Because you left --reasoning-parser completely empty, vLLM disables its automatic sorting boxes.
   2. It turns off both the "Thinking Box" and the "Final Answer Box" separation. It creates just one single giant box (content).
   3. The model reads your manual tags, understands that thinking is closed, and types the final joke.
   4. vLLM takes everything—the tags, the joke, any extra characters—and drops it as raw text into that single content box. Your application gets the exact, unparsed raw string block.

------------------------------
## Scenario 3: The Manual Text Way (But You Still Want Separate Boxes)
What if you want to type the text tags manually, but you still want vLLM to split the output cleanly into the distinct API boxes?
## Setup:

* Your Prompt Looks Like This:

"User: Tell me a joke. <think>\n\n</think>\n\n"

* Server Flag to Use: --reasoning-parser deepseek_r1

## Why Use the DeepSeek flag for a Qwen Model?
This sounds strange, but it works because of how the parser scripts are coded.
The deepseek_r1 parser is a simple, rigid "token-watcher." It does not care about Qwen's internal python template variables. It simply looks at the raw output text stream like a hawk.

* If it sees text before or inside a <think> tag, it throws it into the Thinking Box.
* The moment it sees a </think> tag, it cuts the stream and routes all following text into the Final Answer Box.

Because your manual prompt text mimics a raw DeepSeek string structure, the deepseek_r1 parser parses it perfectly, whereas the qwen3 parser would panic looking for internal template metadata.
------------------------------
## Summary Checklist to Decide

* If you control thinking using Code Parameters (enable_thinking=False) $\rightarrow$ Use --reasoning-parser qwen3.
* If you control thinking by Manually Typing Strings (<think>...</think>) and want raw text $\rightarrow$ Do not use any flag.
* If you control thinking by Manually Typing Strings but still want separate JSON API boxes $\rightarrow$ Use --reasoning-parser deepseek_r1.
