Yes, you can enable or disable “thinking” (reasoning) per request for Qwen3-VL-Thinking models in vLLM by passing the parameter enable_thinking in the request body. 
For Qwen3 series, set extra_body={"chat_template_kwargs": {"enable_thinking": False}} to disable, or True to enable, reasoning for that specific request.

## 📋 Checklist: Disabling Qwen3/3.5 Thinking in vLLM
Ensure the following configuration is met to allow toggles of the enable_thinking parameter per-request without crashing the API server.
## 1. Infrastructure Requirements

* Upgrade vLLM: Confirm the backend is running vLLM v0.9.0 or higher (v0.8.5 and older will crash when thinking is disabled).

## 2. Server Launch Configuration

* Set the Right Parser: Launch the vLLM server using the dedicated Qwen flag:

--reasoning-parser qwen3

(Do not use deepseek_r1 or leave it empty, as those rigid parsers will panic and throw errors when the <think> block is skipped).

## 3. Client API Payload (The Toggle)

* To Turn Thinking OFF: Pass enable_thinking: False inside the request's extra arguments. This forces the model to jump straight to the final answer:

extra_body={
    "chat_template_kwargs": {
        "enable_thinking": False
    }
}

* To Turn Thinking ON: Change the parameter to True (or omit it, as it defaults to true on thinking-capable variants).
